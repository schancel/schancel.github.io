Reproduce this run

One synthetic miner confirms transactions from node 0. Peers form a complete graph; this does not run the full node relay or consensus implementation. Retry delays are uniform from the configured base to twice the base. Quote expiry controls how long a quote remains usable, rather than a periodic refresh. The accepted-transaction policy either retains admitted transactions as the floor changes or rechecks and removes them against the new RPC threshold.

Payment policy: the sender chooses the gross amount G. The wallet automatically quotes a bounded fee F, deducted from gross; the recipient receives a net UTXO of G − F and sees gross, processing fee, and net. The recipient bears this fee economically. Normal wallet use has no routine fee-rate prompt: the controls here are research controls. Invoice maximum-fee and minimum-net limits use quiet defaults; when a payment cannot fit them, the wallet defers it with a clear reason. The simulated cap is the smaller of the sender class budget and gross minus minimum recipient net. All amounts use the same native fee asset. This wallet policy requires no consensus change, auction, or refund.

The 100× preset gives humans a baseline bid of 100,000 atoms / 1,000 bytes (0.1 XPI / kB), versus 1,000 (0.001 XPI / kB) for background traffic, with ±1% jitter. Jitter near an exact floor can cause refusal; vary it to test the boundary. Fixed wallets use the chosen shared or cohort baseline. Reactive wallets bid the greater of that baseline and the controller SDK quote, subject to their transaction budget.

In synthetic disk mode, admitted transaction bytes enter a modeled write queue that drains at the configured rate. The actual controller congestion formula runs on this modeled queue. No measured disk I/O, unit-price forecast, or supply assumption is involved.

Real primitives. Synthetic market.

The compiled C++ simulator uses actual CFeeRate and FeeHysteresisController primitives and the shared relay EventLoop/VirtualNetwork. Wallets, mempools, and miners are synthetic actors. This is not full node validation, signature verification, or a benchmark of real CPU/network performance.

Sender classes receive no privileged priority: equal visible bids are interchangeable. Under overload, identical bids cannot all confirm; spam can outbid other senders. Fees use atoms: 1,000 atoms / 1,000 bytes = 1 atom / byte. One XEC = 100 atoms; one XPI = 1,000,000 atoms.
